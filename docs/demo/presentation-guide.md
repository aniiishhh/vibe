## Reproduce or resume

`demo/presentation-scenarios.json` contains fictional human openings and approved preference points, adapted from the supplied `Downloads/demo-scenarios.md`. `scripts/seed-presentation-demo.mjs` sends them through the deployed authenticated app APIs and waits for actual responses. Dynamic class follow-ups use returned class/instructor evidence. Existing fixture checkpoints prevent repeating completed messages.

Offline inspection requires Node 24 and makes no AWS/provider requests:

```sh
node scripts/seed-presentation-demo.mjs plan
```

Live execution additionally requires AWS CLI credentials authorized for shared account `851725603471`, Ohio, and explicit permission to create persistent demo data. The script guards the account, Cognito pool, response model and user identities. It uses admin-created confirmed example.com accounts with email suppressed; this does not demonstrate inbox signup. Credentials and checkpoints stay under ignored `.demo/`, with restrictive permissions. A fresh checkout has no private state and will create new fixtures; do not run it merely to open the existing conversations.

Run phases sequentially, inspecting actual replies between phases:

```sh
export AWS_PROFILE=vibe-team VIBE_DEMO_ALLOW_LIVE=yes
node scripts/seed-presentation-demo.mjs setup
node scripts/seed-presentation-demo.mjs classes
node scripts/seed-presentation-demo.mjs class-clarification
node scripts/seed-presentation-demo.mjs trip
node scripts/seed-presentation-demo.mjs hackathon
node scripts/seed-presentation-demo.mjs summary
```

The summary checks saved user identities, message counts, run outcomes, tasks and themes. It writes `.demo/presentation-summary.json` privately. Keep this branch's scripts separate from application deployment; no deployment is needed to use the saved chats. Validation for this contribution covers syntax, JSON/whitespace, live saved runs and task states; unchanged application code did not require another broad regression run.
